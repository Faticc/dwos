# DwOS

Операционная система для OpenComputers — OpenOS 1.8.8, переписанный заново.
Оболочка та же, команды те же, а внутри всё собрано под то, как мод считает
время: экранные вызовы тратят бюджет тика, вызовы к видеопамяти — нет,
поэтому графика в системе рисуется в буфер, а на экран уходит только то, что
изменилось.

Что получилось сверх привычного OpenOS:

* **install** рисует окно: стрелками выбираешь диск, Enter соглашается,
  внизу идёт полоса хода. `install --text` ведёт себя ровно как в OpenOS,
  так что лут-дискеты (`install oppm`) ставятся как раньше.
* **edit** — не просто редактор, а среда для Lua. Подсветка, выделение
  Shift+стрелками и мышью со своим буфером обмена, отмена и повтор,
  подсказка слова прямо при наборе и дополнение по Tab (включая поля живых
  таблиц и методы подключённых устройств с их описанием из мода),
  автоотступ и парные скобки, поиск и замена по шаблону Lua.
  Файл проверяется на ходу: синтаксис и подозрительные имена — опечатка в
  `pritn`, забытый `local`, ни разу не использованная переменная; F8 ведёт
  от ошибки к ошибке. По коду можно ходить: Ctrl+T — функции файла,
  F12 — к определению (по `require` — прямо в модуль), Shift+F12 — где
  ещё стоит эта переменная, F2 — переименовать её во всей области
  видимости, Ctrl+B — назад. Открытых файлов может быть несколько
  (Ctrl+P, Ctrl+PgUp/PgDn). F5 сохраняет и запускает файл в панели внизу,
  Ctrl+E открывает там же оболочку, а F6 запускает программу под
  отладчиком: F9 ставит точки останова, F10/F11 шагают (F11 у Minecraft
  занята полным экраном, поэтому те же шаги висят на F7 и на буквах),
  справа видно значения видимых переменных. Раскладка читается из `/etc/edit.cfg`,
  чего в файле нет — берётся по умолчанию, так что старый конфиг ничего
  не ломает.
* **less** листает в обе стороны и умеет искать по `/`; `more` (`less
  --noback`) по-прежнему просто гонит текст по терминалу.
* **sysmon** — монитор: графики памяти и энергии полублоками, аптайм,
  железо, занятое место на дисках.
* **bench** — бенчмарк на девять проб, у каждой своя живая картинка:
  «Жизнь» Конвея, множество Мандельброта, плазма, вращающийся 3D-тор,
  сетка блоков диска. В конце — итог в очках крупными цифрами (1000 —
  эталонная машина), сравнение с прошлым запуском и рекордом.
* **update** — одна команда на всё, что стоит: систему, игры, ролики,
  программы. Сверяет с репозиторием по манифестам с CRC32, качает только
  изменившееся, проверяет скачанное и лишь потом подменяет файл. Это
  `get update`: состояние, раскладка по дискам и ключи общие.
* **get** — игры, программы и сама система одной командой: `get` покажет,
  что есть в репозитории (система, `games/`, `apps/`), что уже стоит и
  сколько места на каждом диске, `get install mario bank` поставит,
  `get update` обновит всё разом, `get remove` уберёт. Ролики качает
  сжатыми двойниками — на треть легче.
* **get сам раскладывает по дискам.** Игра, ролик, набор программ лежат
  каждый целиком на одном диске (игра читает свои файлы из своего
  каталога, плеер ищет звук рядом с роликом). Новое ложится в
  `/home/games`, `/home/videos`, `/home/dwapps`, а не влезает — на диск,
  где свободнее: `/mnt/xxx/games`, `/mnt/xxx/videos`. Крупное
  раскладывается первым, дискеты `get` сам не занимает, на системном
  диске оставляет 64 КБ запаса; обновлению, которому стало тесно на своём
  диске, находится другой — позиция переезжает целиком. `--disk=/mnt/xxx`
  кладёт туда, а с `install` — и переносит уже стоящее. Места нет нигде —
  скажет до загрузки, что именно не влезает и где свободнее всего.
* **Сеть выжата до потолка карты.** Интернет-карта берёт тик за каждый
  запрос и по два тика за каждые 2 КБ — около 20 КБ/с, быстрее не
  бывает. Всё остальное `lib/fetch.lua` убирает: просит у GitHub gzip и
  распаковывает сам (код приходит втрое меньше), держит четыре запроса
  разом, не тратит лишних чтений в конце файла, а установка с нуля и
  большое обновление идут одним сжатым пакетом всей системы. По модели
  карты в эмуляторе установка на дискету — около 10 с вместо полутора
  минут, `update` почти всей системы — 8 с; `wget` тоже качает сжатым.
* **man** по-русски: страница на каждую команду, `man` без довода
  показывает список тем. В сборке страницы сложены в один файл с
  оглавлением — на дискете полсотни отдельных файлов стоили бы 32 КБ одними
  служебными хвостами.
* **Ctrl+Alt+C** убивает программу, но больше не роняет саму оболочку с
  трассой на весь экран. Программа может закрыться и от него:
  `process.killable(false)` — тогда вместо смерти ей придёт обычное
  `interrupted`, и что с ним делать, решает она.
* `_OSVERSION = "DwOS 1.0"`, приветствие с советами, заставка при загрузке.

## Установка

Нужен компьютер с OpenOS, интернет-картой и **чистой дискетой**:

```
wget -f https://raw.githubusercontent.com/Faticc/dwos/main/install.lua /tmp/i.lua && /tmp/i.lua
```

Установщик покажет список дисков (дискеты первыми), скачает сборку по
манифесту и поставит дискете метку `DwOS`. Дальше вставляешь дискету в
машину, где она видна первой, загружаешься с неё и набираешь:

```
install
```

Система переедет на жёсткий диск, сделает его загрузочным и предложит
перезагрузиться. Установщик ставит только систему; игры, ролики и
программы — дальше, из самой DwOS:

```
get                    что есть
get install mario bank
get install games      все игры разом
```

Обновить всё, что стоит, — система, игры, ролики, программы — одной
командой:

```
update
```

`update --dry` покажет, что изменится; `update mario` — только это. У
веб-установщика ключи свои: `--repo=владелец/репо`, `--branch=ветка`,
`--dir=подкаталог`, `--dry`, `--force`.

## Что где лежит

```
install.lua   веб-установщик на дискету (запускается под OpenOS)
os/           исходники системы, с комментариями
dist/         то же без комментариев + manifest.lua — это качает установщик;
              all.gz — вся сборка одним сжатым пакетом (на дискету не ложится)
games/        игры и ролики (manifest.lua с частями) — ставит get
apps/         программы: банкомат, админка — ставит get
```

Внутри `os/` структура как у OpenOS: `init.lua`, `boot/`, `lib/`, `bin/`,
`etc/`, `usr/`, `home/` и `.prop` — файл, по которому установщик понимает,
что это установочный носитель.

Сборщик `tools/dwosbuild.py` и проверки (`test/ocvm.lua` — эмулятор машины
OpenComputers на Lua 5.4, `test/ostest.lua`, `test/dwostest.lua`) живут в
репозитории разработки рядом с исходниками мода.

## Сборка и проверка

```
python tools/dwosbuild.py
```

Сборщик лексером Lua снимает с кода комментарии, отступы и пробелы между
знаками (строки и длинные скобки не трогает, `#!` сохраняет), выбрасывает
опустевшие строки, даёт локальным переменным однобуквенные имена (поля и
глобальные не трогает), пишет `dwos/dist/` и `manifest.lua` с размером и
CRC32 каждого файла. Ужатое сверяется с исходником по байткоду `luac -s`: если
программа стала хоть чем-то другой, сборка не проходит. В конце считает,
влезает ли это на дискету 512 КБ — помни, что каждый файл и каталог съедает
ещё 512 байт сверх своего размера.

Проверки:

```
lua test/ostest.lua           136 команд на DwOS и OpenOS, сверка экранов
lua test/dwostest.lua         дискета → install на HDD → less, edit, sysmon → update
lua test/edithar.lua          edit: проверки, навигация, замена, отладчик
lua test/inflatetest.lua      lib/inflate.lua против настоящего zlib
```

`ostest` держит DwOS рядом с оригиналом: из 136 команд расходятся три, и все
намеренно. `time` показывает настоящее время процессора; `man` без довода
печатает список тем вместо короткой подсказки; `ls -S` при равных размерах
сортирует по имени, а не в том порядке, в каком файлы вернула файловая
система.

## Почему в системе своя графика

Прямой вызов к видеокарте стоит `1/limit` бюджета тика: `set` на карте
третьего уровня — 1/256, `fill` — 1/128, `copy` — 1/64. Вызовы к буферу
видеопамяти бесплатны, зато `bitblt` грязного буфера на экран стоит
`2.0 · (w·h)/8000` — полноэкранный буфер съедает целый тик.

Отсюда правило, по которому живёт `lib/gfx.lua`: изменения копятся в
журнале, и если их мало, они повторяются прямо на экране (десяток `set`
дешевле тика ожидания), а если много — уходит одним `bitblt`. Поэтому
терминал работает напрямую, а окна `install`, `edit`, `less` и `sysmon`
рисуются через холст: правка одной строки в редакторе стоит десяток
вызовов, а не перерисовки всего экрана.

Где проходит граница, решает цена: повтор выбирается, пока он дешевле
`bitblt` этого буфера и не съедает больше двух третей кредита тика
(`gfx.budget`). Порог подобран замером — `lua test/gamevm.lua` гоняет на
эмуляторе игры, которые рисуют через тот же холст; ниже порога кадры
теряются зря, выше — повтор забирает тик, который и так пришлось бы
отдать `bitblt`.

Холстов два: `gfx.surface` — текстовый (`set`/`fill`/`copy`, как у
видеокарты, но в буфер), `gfx.new` — пиксельный, где полублок делит ячейку
на две точки, так что 160×50 символов превращаются в 160×100 точек. Без
видеопамяти оба рисуют прямо на экран — медленнее, но работают.
